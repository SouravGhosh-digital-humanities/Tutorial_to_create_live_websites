# Digital Humanities Web Tutorial

A beginner-friendly tutorial for students of the **Digital Humanities**
who want to learn how to create, style, and publish a simple static
website using **HTML, CSS, GitHub, and GitHub Pages**.

## About the Project

This project is based on my **ideas, pedagogical design, and teaching
objectives**. The website and supporting materials were **generated and
implemented with ChatGPT as an AI assistant**.

The intellectual conception, subject focus, pedagogical purpose, and
organisation of the tutorial are my own. ChatGPT was used as an
implementation and development assistant.

## Learning Objectives

By completing this tutorial, students will learn how to:

-   create a basic `index.html` file;
-   understand the structure of an HTML document;
-   use semantic HTML elements;
-   create hyperlinks and internal page navigation;
-   apply CSS for typography, colour, spacing, and layout;
-   understand the CSS box model;
-   create a responsive webpage;
-   create and manage a GitHub repository;
-   upload a static website to GitHub;
-   publish a website using GitHub Pages;
-   understand the webpage as a **scholarly and interpretive
    interface**.

## Why This Matters to the Digital Humanities

Web development in the Digital Humanities is not simply a technical
activity. A webpage can function as an **interpretive interface**
through which users encounter texts, archives, images, metadata,
datasets, editions, exhibitions, and scholarly arguments.

The tutorial therefore introduces HTML and CSS alongside questions
about:

**structure, metadata, accessibility, navigation, visual hierarchy,
interpretation, and digital scholarly communication.**

Students are encouraged to think critically about how technical and
visual decisions influence the way knowledge is presented and
understood.

## Project Structure

The basic project contains:

``` text
Tutorial_to_create_live_websites/
│
├── index.html
└── README.md
```

The `index.html` file contains the complete tutorial webpage, including
its CSS. No external framework or stylesheet is required.

## How to Use the Tutorial

### 1. Download or clone the repository

Students can obtain the project from GitHub and open `index.html` in a
web browser.

### 2. Read the tutorial sequentially

The tutorial is organised into four broad parts:

1.  **HTML**: document structure and semantic markup.
2.  **CSS**: styling, layout, and responsive design.
3.  **GitHub Pages**: repository creation and website publication.
4.  **Student Exercise**: creating an individual Digital Humanities
    project page.

### 3. Modify the examples

Students should replace the example material with the content of their
own research project.

Possible projects include:

-   digital archives;
-   textual studies;
-   bibliographic projects;
-   digital exhibitions;
-   literary mapping projects;
-   corpus-based projects;
-   historical research projects;
-   metadata projects;
-   digital editions.

## Publishing with GitHub Pages

After uploading `index.html` to the repository, GitHub Pages can be used
to publish the webpage.

The basic workflow is:

``` text
HTML/CSS
   ↓
GitHub Repository
   ↓
GitHub Pages
   ↓
Public Website
```

The repository should contain `index.html` in its main/root directory.

## Student Exercise

Create a small Digital Humanities project webpage.

The page should contain:

-   a meaningful project title;
-   a short project description;
-   at least three semantic HTML sections;
-   one external hyperlink;
-   one internal page link;
-   CSS for typography, colour, spacing, and layout;
-   a responsive design;
-   a short bibliography or source section.

Students should then publish the project using GitHub Pages.

## Critical Reflection

After completing the exercise, consider:

1.  How does the structure of the webpage influence interpretation?
2.  Which information receives visual prominence?
3.  What materials have been included or excluded?
4.  How does metadata influence discoverability?
5.  How does navigation shape the reader's experience?
6.  In what sense can the interface itself function as a scholarly
    argument?

These questions encourage students to understand digital humanities
projects as **designed knowledge environments**, rather than merely as
containers for information.

DH Web Tutorial
Learn HTML CSS GitHub Exercise
Digital Humanities · Beginner Tutorial

Build and publish your first static website.

This tutorial teaches students how to create a simple website with HTML and CSS, understand the structure of a web document, and publish the finished page through GitHub Pages.

Learning objective: By the end of this tutorial, you should be able to create an index.html file, add semantic HTML, style it with CSS, save it in a GitHub repository, and publish it as a public webpage.

What You Will Learn

The tutorial moves from webpage structure to publication.

A

Four stages of the tutorial

HTML: Learn how to structure and semantically describe a webpage.
CSS: Learn how to control typography, colour, spacing, layout, and responsive behaviour.
GitHub: Learn how to store and manage your webpage in a repository.
GitHub Pages: Learn how to publish the webpage as a public website.
REFLECT: In Digital Humanities, these technical stages are connected to questions of representation, access, metadata, interpretation, and scholarly communication.

Before You Begin

Prepare the small set of tools required for this tutorial.

B

What you need

READ: You do not need advanced programming knowledge.

☐ Web browser: Chrome, Firefox, Edge, Safari, or another modern browser.

☐ Text editor: VS Code, Notepad++, Sublime Text, or another plain-text editor.

☐ GitHub account: Required for creating the online repository.

☐ File-management skills: You should know how to create a folder, save a file, rename a file, and upload a file.

DO: Create a folder called digital-humanities-website on your computer. This will be your working directory.
CHECK: Make sure you can locate the folder and open your text editor before continuing.

Part I: HTML

HTML provides the structure and semantic meaning of a webpage.

1

Create a file called index.html

READ: Create a new folder on your computer. Inside that folder, create a file named index.html.

The filename matters because index.html is commonly used as the default entry page by web servers and GitHub Pages.

Digital Humanities connection: A static webpage can function as a small scholarly interface. For example, you might use it to present a digital archive, research project, textual corpus, exhibition, map project, or bibliographic resource.
2

Write the basic HTML skeleton

Start with this structure:

<!doctype html>
<html lang="en-GB">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Digital Humanities Project</title>
</head>

<body>
  <h1>My Digital Humanities Project</h1>
  <p>This is my first webpage.</p>
</body>
</html>
Key concept: element. An HTML element is a structural unit such as <h1>, <p>, or <section>. Elements tell the browser what different pieces of content mean.
DO: Change the text inside <h1> to the title of your own research project. Open the file in a browser.
CHECK: Confirm that the browser displays your new title.
3

Add semantic HTML

READ: Do not treat HTML as merely a way to make text appear on a screen. Semantic HTML gives content a meaningful structural role. 

<header>
  <h1>Digital Archive of Modernist Poetry</h1>
</header>

<main>
  <section>
    <h2>About the Archive</h2>
    <p>This project documents...</p>
  </section>

  <section>
    <h2>Primary Sources</h2>
    <p>The collection contains...</p>
  </section>
</main>

<footer>
  <p>Digital Humanities Project, 2026</p>
</footer>
Key concept: semantic markup. Semantic markup distinguishes content by function. For example, <nav> identifies navigation, while <article> identifies a self-contained piece of content. This improves accessibility and machine readability.
4

Add links

Hypertext is central to both the web and many Digital Humanities projects. An anchor element creates a link. 

<a href="https://github.com/">
  Visit GitHub
</a>

You can also link to another section of the same page: 

<a href="#sources">Go to Sources</a>

<section id="sources">
  <h2>Sources</h2>
</section>

Part II: CSS

CSS controls the visual presentation of HTML.

5

Add CSS inside the HTML file

READ: For this tutorial we use an internal stylesheet. Put your CSS between <style> and </style> inside the <head>. 

<head>
  <style>
    body {
      font-family: Arial, sans-serif;
      color: #182230;
      background: #f4f6f8;
    }

    h1 {
      color: #8a3ffc;
    }
  </style>
</head>
Key concept: selector. A CSS selector identifies the HTML element that should receive a style. In h1 { color: purple; }, the selector is h1.
6

Understand the CSS box model

Every visible HTML element can be understood through the box model: content, padding, border, and margin. 

.card {
  padding: 24px;
  border: 1px solid #ddd;
  margin: 20px 0;
}

Here, padding creates space inside the element, border creates its visible boundary, and margin creates space outside the element.

7

Create a simple responsive layout

Responsive design allows the same webpage to adapt to different screen sizes. 

.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}

@media (max-width: 700px) {
  .cards {
    grid-template-columns: 1fr;
  }
}
Key concept: media query. A media query applies CSS conditionally. Here, three columns become one column when the viewport is narrower than 700 pixels.

Part III: Publish with GitHub Pages

GitHub can host a static HTML/CSS website without a traditional web server.

8

Create a GitHub repository

DO: Sign in to GitHub and create a new repository. Give it a clear name, such as digital-humanities-website.

For a classroom exercise, a public repository is usually the simplest option if the project contains no restricted material.

Key concept: repository. A repository is a project space that stores files and their version history. Git is the version-control system commonly used to track those changes.
9

Upload index.html

DO: Upload your index.html file to the root of the repository. The structure should look approximately like this: 

digital-humanities-website/
└── index.html

For the first exercise, keep the project deliberately simple. Students can add images, CSS files, JavaScript, data files, and other resources later.

10

Enable GitHub Pages

DO: In the repository, open Settings, find Pages, and configure the site to deploy from the repository's main branch.

GitHub will generate a public URL for the site. The exact interface can change, because software companies enjoy moving buttons when nobody is looking, but the conceptual workflow remains: 

Local HTML file
      ↓
GitHub repository
      ↓
GitHub Pages
      ↓
Public webpage
11

Understand the Digital Humanities workflow

The important lesson is not merely how to publish a webpage. The workflow introduces a basic model of digital scholarship: 

Research question
      ↓
Digital materials
      ↓
Data / texts / images
      ↓
Encoding and metadata
      ↓
Interface
      ↓
Public interpretation

HTML is therefore not only a technical tool. It can become an interpretive interface: a structured environment through which readers encounter an archive, corpus, edition, exhibition, or argument.

Part IV: Student Exercise

Build a small Digital Humanities project page.

12

Build your own project page

Create an index.html page for a hypothetical or real Digital Humanities project.

Required: Give the page a meaningful title.

Required: Add a short project description.

Required: Use at least three semantic sections.

Required: Add one external hyperlink.

Required: Add one internal anchor link.

Required: Use CSS for typography, colour, spacing, and layout.

Required: Make the page readable on a mobile screen.

Required: Upload the file to GitHub.

Required: Publish it using GitHub Pages.

Extension task: Add a section containing a small bibliography. Then experiment with an HTML table for metadata such as author, date, genre, location, or source.
13

Questions for critical reflection

After publishing the page, consider the following questions:

How does the structure of the webpage influence the reader's interpretation of the research? What information becomes prominent because of the visual hierarchy? Which materials are included or excluded? How does metadata shape discoverability? How might the interface itself function as an argument?

Digital Humanities principle: A digital project is not simply a container for research. Its interface, metadata, encoding, navigation, and technical infrastructure can all participate in scholarly interpretation.
14

Final Reflection

REFLECT: A successful webpage is not only technically functional. Ask how its structure, metadata, visual hierarchy, navigation, and accessibility shape the reader's encounter with your material.

CHECK: Before submission, explain in two or three sentences how one design or structural decision in your webpage affects its scholarly meaning.
15
